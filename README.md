# 市民篮球场 · 预约拼场 / 照明计费 / 冲突调解（移动端 H5 演示）

一个面向**手机现场操作**的单页应用：市民按场地、半场/全场、时间段、人数、是否拼场、是否需要夜间照明预约公共篮球场；队长邀请队员签到、散客申请拼场；管理员在后台看到每个时段的预约人数、实际到场、支付状态与冲突风险；社区工作人员处理噪声投诉、未成年人夜留与篮筐争议。**雨后巡查发现半场积水时，页面把该时段预约队伍、已支付照明费、可替代场地和改约窗口集中公示，队长可四选一（退款 / 顺延 / 改室内场 / 半场拼场），结果同步队员与散客；已到场热身的队伍登记到场人数与等待时长，退款补偿区别于完全未到场的预约。** 所有费用变化、退款补偿、处罚记录都与具体规则条文（编号 R-xxx）一一关联、可点击查看。

技术栈：**Vue 3 + TypeScript + Vite + Naive UI**，纯前端 + 内置 mock 数据与响应式规则引擎，无需后端即可完整演示全部流程。

## 本地启动

```bash
npm install
npm run dev        # http://localhost:5173 （已监听 0.0.0.0，手机局域网可访问）
```

其他命令：

```bash
npm run build      # vue-tsc 类型检查 + 生产构建到 dist/
npm run preview    # 预览生产构建
npm run typecheck  # 仅类型检查
npm run smoke      # 核心业务规则断言冒烟测试（esbuild 打包后在 Node 执行）
```

### 一键 Docker 启动（无需 Node 环境）

```bash
docker compose up -d --build    # 构建并后台启动
# 浏览器打开 http://localhost:8080
docker compose logs -f court-booking
docker compose down             # 停止
```

镜像为多阶段构建：Node 构建静态产物 → nginx 托管（含 SPA 路由回退与资源缓存）。

建议用浏览器 DevTools 切换到手机视口（如 iPhone 390×844）体验；页面最大宽度 480px 居中。

## 建议的验证路径（均为可在页面上实际操作的流程）

1. **预约**：场地预约 → 选择 B区/河滨球场 → 半场/全场、时段（已满/故障/维修的半场自动禁用）、人数（低于建议下限会提示拼场）、勾选接受拼场与夜间照明 → 看到押金与预估费用 → 提交后在「我的队伍」出现签到码。
2. **队长签到与照明计费**：我的队伍 → B001 晨光队 → 邀请队员、逐个签到；推进时钟，观察"还能打多久"、照明分钟数、实时金额（拼场 8 折、按签到人数平摊）；点「结束使用并关灯」按实际时长结算，押金余额退还。
3. **散客拼场**：切到王同学 → 拼场签到页对晨光队的申请显示"待处理"；切回队长**同意**后散客可凭码签到；也可找其他队伍新申请，队长拒绝时必须填写正当理由，否则产生 20 元资源占用费与信用扣分。
4. **迟到 / 爽约 / 超时**：B002 散客联队预置了迟到 23 分钟与无理由拒拼扣费；把时钟推过某待开场场次开场 20 分钟，看板/后台出现「释放场地」（R-LATE-1）；对进行中场次持续推时过 20:05 可见超时费 2 元/分钟、超 15 分钟可强制清场（R-OT-2）；B006 是已结算的超时案例。
5. **照明故障（I-005）**：事件页 → B区 H1 故障工单 → 管理员核验后由队伍三选一：等维修 / 改约（押金全退、优先排位）/ 全额退款，费用计时此前已自动冻结（R-LIGHT-3）。
6. **下雨地滑 / 篮筐维修**：后台「场地状态控制」可发布积水暂停/湿滑/恢复（R-WX-1）；B005 预置了篮筐紧急维修改约 + 5 元交通补偿案例（R-WX-2）；I-002 是已裁决的争抢篮筐工单（R-DISPUTE-1）。
7. **🌧️ 雨后三号场积水暂停与改约（本次新增，R-WX-3）**：预置工单 **I-007**（河滨灯光球场 H1/H2/H3 积水，19:40 发布、选择窗口 **19:55** 截止、预计 20:30 恢复）：
   - **事件处置页**打开 I-007：面板集中展示该时段两支预约队伍——烈风队 B003（全场 H1/H2，已付押金 100 元 + 暂停前照明费，**9 人已到场热身**）、晚风女篮 B011（H3，押金 50 元，**完全未到场**），以及不受影响可拼场的 H4 夜训小组 B012；
   - 管理员可点验/修正**到场人数、是否热身**，面板实时显示等待时长与阶梯补偿（<15 分钟 5 元 / 15–29 分钟 10 元 / ≥30 分钟 15 元 + 免费券；未到场无补偿）；
   - 每队可四选一：**全额退款**（押金原路退、暂停前照明免收，到场队另拿等待补偿）/ **顺延**（今晚恢复后 20:30 或明日同时段，押金平移）/ **改到室内场**（邻里中心室内篮球馆 20:00–22:00，生成新预约与新签到码）/ **接受半场拼场**（并入 H4 夜训小组，队员与押金平移、拼场 8 折）；
   - 选择结果写入时间线并**同步全体队员与散客申请者**（王同学的 MR-4 自动转挂到新场次，散客页"我的拼场申请进度"可见"场地变更·已同步"）；两队全部安置后工单自动办结，管理员可"复查确认积水清除"解除暂停；
   - 把演示时钟从 19:42 推到 19:55 / 20:10，观察窗口倒计时与等待补偿升档；也可在管理后台「🎛️ 场地状态控制 → 巡查发现积水·发布暂停」对 A 区重新发起完整流程。
8. **噪声投诉 / 未成年人夜留**：以社区工作人员身份处理 I-001（首次劝导 vs 24h 内第 2 次核实收 50 元，R-NOISE-1）、I-004（监护人接回登记，R-MINOR-1）。
9. **封场（I-006）**：管理员对河滨 H3/H4 的社区活动工单签发封场令 → 仅受影响的 B009 被中止、押金全退、可免费改约；同场地 21:00 正好结束的 B012（H4）与正在打球的 B003 不受影响；场地页/看板对应半场显示"封停"（R-SEAL-1）。
10. **现场看板**：任意身份都能看到每个半场当前使用者、签到码、到场人数、剩余/超时时间，积水半场显示斜纹"积水暂停"覆盖与各队安置状态，以及争议时"预约码→时段比对→先到先得+信用分"的判断指引。
11. **公平性解释**：管理后台有黄金时段固定队 ≤60% 的配额条；规则页顶部给出改约优先级链（安全维修 > 已支付已签到 > 固定队 > 先到先得 > 信用分），每张被改约卡片（B005/B009 等）都有管理员说明与规则编号，解释"为什么是这一方被改约/限制"（R-FAIR-1~4）。

## 页面与模块

```
src/
├─ App.vue                 手机外壳、顶栏角色切换、演示时钟、底部导航、通知
├─ types.ts                领域模型（场地/预约/队员/费用条目/事件工单/拼场申请…）
├─ store.ts                响应式状态 + 全部业务动作（预约/签到/拼场/照明结算/释放/封场/改约/处罚）
├─ data/
│  ├─ mock.ts              4 片场地（含室内馆）、12 个预约、7 个事件工单（覆盖题目全部情形）
│  └─ rules.ts             21 条规则条文（预约拼场/到场超时/照明/天气/争议/噪声/公平）
├─ lib/
│  ├─ engine.ts            规则引擎：实时照明计费、迟到/超时、费用汇总、冲突风险、占用/释放、拼场正当性、积水安置方案与等待补偿试算
│  └─ ui.ts                标签页与规则跳转总线
├─ components/
│  ├─ BookingCard.vue      预约卡片：剩余时间、到场、实时照明费、费用变化、权益时间线、积水暂停横幅
│  ├─ RainSuspensionPanel.vue 雨后积水改约窗口：受影响队伍/已付照明费/替代场地/到场等待登记/四选一/队员散客同步
│  ├─ RiskTag.vue          风险标签（点击展开原因）
│  ├─ RuleLink.vue         规则编号链接（跳到规则页并高亮）
│  └─ BottomSheet.vue      移动端底部抽屉
└─ pages/
   ├─ CourtsPage.vue       场地状况（地面/篮筐/敏感小区/更衣柜/照明收费/室内标识）+ 预约表单 + 现场上报 + 今日占用
   ├─ MinePage.vue         队长（邀请/签到/拼场审核/照明/结算/积水安置入口）与散客（签到码/找拼场/申请进度与转挂同步）
   ├─ BoardPage.vue        现场看板：谁在用、还能打多久、积水暂停覆盖、释放/强制清场、争议判断指引
   ├─ AdminPage.vue        后台：时段维度预约人数/到场/支付/风险、场地控制、巡查发布积水暂停、改约、公平性配额
   ├─ IncidentsPage.vue    事件工单：积水改约面板、现场核验、退款补偿、投诉答复、处罚全流程留痕
   └─ RulesPage.vue        规则原文与公共资源公平性说明
```

## 已执行的验证

- `npm run build`（含 `vue-tsc --noEmit` 全量类型检查）通过，产物输出到 `dist/`。
- 所有 `.vue` 单文件组件通过 `@vue/compiler-sfc` 模板解析与 Vite 生产构建（2696 个模块转换成功）。
- 核心业务规则的 **47 项断言冒烟测试全部通过**（`npm run smoke`，用 esbuild 打包后在 Node 执行 `src/store.ts + src/lib/engine.ts`），覆盖：
  - 照明实时计费（按实际开灯分钟，如 B002 18:25→19:42 共 77 分钟；拼场 8 折按签到人均摊）；
  - 无理由拒拼收 20 元 + 信用扣 5 分；
  - 押金 50 → 实际照明 8 元 + 拒拼 20 元 → 退 22 元的结算链；
  - 开场 20 分钟未签到可释放（爽约规则）；
  - 照明故障核验后全额退款、已计照明费免收、工单办结；
  - 封场仅作用于 H3/H4 且按时段重叠过滤（B009 封场退款；21:00 正好结束的 B012 不受影响）；
  - **雨后积水（R-WX-3）**：三号场 H1/H2/H3 暂停后自动关联 B003/B011（H4 的 B012 不受影响）；到场等待补偿阶梯 5/10/15 元 + 满 30 分钟赠券，未到场无补偿；全额退款（押金 100 退回 + 到场安抚 5 元）、改室内（生成新预约、押金 50 平移、队员签到清零、无等待补偿）、半场拼场（7 名队员并入 B002、押金 50 平移、散客 MR-1 自动转挂）、顺延（当晚 20:30 新场次押金平移）；散客 MR-4 标记 superseded 同步；全部安置后工单自动办结、复查解除半场暂停；管理员新发布暂停自动关联队伍、关灯冻结、按半场精确关联。
