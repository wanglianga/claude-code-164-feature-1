# 市民篮球场 · 预约拼场 / 照明计费 / 冲突调解（移动端 H5 演示）

一个面向**手机现场操作**的单页应用：市民按场地、半场/全场、时间段、人数、是否拼场、是否需要夜间照明预约公共篮球场；队长邀请队员签到、散客申请拼场；管理员在后台看到每个时段的预约人数、实际到场、支付状态与冲突风险；社区工作人员处理噪声投诉、未成年人夜留与篮筐争议。所有费用变化、退款补偿、处罚记录都与具体规则条文（编号 R-xxx）一一关联、可点击查看。

本题新增：**雨后地滑的场地暂停与改约**——管理员巡查发现三号场（河滨公园灯光球场）积水后一键发布暂停，页面集中展示**该时段预约队伍、已支付照明费、可替代场地与改约窗口**；队长四选一（**退款 / 顺延 / 改到室内场 / 接受半场拼场**），结果实时**同步队员与拼场散客**（避免白跑）；已到场热身的队伍按**到场人数与等待时长**发放等待补贴，与完全未到场的预约差异化结算（R-WX-3）。

技术栈：**Vue 3 + TypeScript + Vite + Naive UI**，纯前端 + 内置 mock 数据与响应式规则引擎，无需后端即可完整演示全部流程。

## 本地启动

```bash
npm install
npm run dev        # http://localhost:5173 （已监听 0.0.0.0，手机局域网可访问）
```

其他命令：

```bash
npm run build      # vue-tsc 类型检查 + 生产构建到 dist/
npm run preview    # 预览生产构建
npm run typecheck  # 仅类型检查
npm test           # 冒烟测试：36 项断言（积水暂停全流程 + 既有规则回归）
```

## 本题的验证方式（雨后积水暂停与改约，均为页面可操作流程）

1. **发布暂停**：切到「📋 老周（管理员）」→ 管理后台顶部「🌧️ 雨后积水暂停与改约」→ 默认已选**河滨公园灯光球场（三号场）**、预计恢复 21:00 → 点「发布积水暂停」。页面立即展示：**该时段 3 支预约队伍**（烈风队 B003 到场 9 人、晨光二阵 B011 到场 4 人、清风队 B012 完全未到场）、**已支付照明费**（押金 + 暂停前实际照明费，计费已冻结）、**可替代场地**（室内馆今日空闲时段、B区 H1 空闲半场）、**改约窗口**（顺延明日同时段 / 室内场 / 半场拼场）。
2. **等待时长累计**：点顶部时钟 `+10分`，各队伍的"已等待"分钟数实时增长；等待超 30 分钟，补贴预估自动 +10 元。
3. **队长四选一**：切到「🏀 陈晨（队长）」→ 我的队伍 → 晨光队·二阵 B011 顶部出现处置卡，可看到到场 4 人、等待时长、补贴预估与四个选项的具体去向，选择「🏢 改到室内场」→ 卡片显示改约结果与"已同步：队员 7 人、拼场散客 1 人"。
4. **散客同步**：切到「🏃 王同学」→ 拼场签到 →「我的拼场申请」中 B011 显示积水处置结果（改约至室内馆 20:00–22:00，拼场权益延续）；若队长选的是退款，则提示申请随场次取消、未产生费用。
5. **差异化补偿**：切回管理员，对 B003（到场 9 人）代录「顺延」→ 补贴 9×3+10=37 元、照明按实际 40 分钟计 64 元；对 B012（完全未到场）代录「全额退款」→ 押金 50 元全退、**无等待补贴**——与到场队伍的差异在费用条目中逐条可查（R-WX-3）。
6. **恢复使用**：管理员点「积水已清·恢复使用」→ 场地标记为湿滑、工单办结；事件处置页可查看 I-007 工单完整留痕（发布 → 各队选择 → 恢复）。

## 既有功能的验证路径

1. **预约**：场地预约 → 选择 B区/河滨球场 → 半场/全场、时段（已满/故障/维修的半场自动禁用）、人数（低于建议下限会提示拼场）、勾选接受拼场与夜间照明 → 看到押金与预估费用 → 提交后在「我的队伍」出现签到码。
2. **队长签到与照明计费**：我的队伍 → B001 晨光队 → 邀请队员、逐个签到；推进时钟，观察"还能打多久"、照明分钟数、实时金额（拼场 8 折、按签到人数平摊）；点「结束使用并关灯」按实际时长结算，押金余额退还。
3. **散客拼场**：切到王同学 → 拼场签到页对晨光队的申请显示"待处理"；切回队长**同意**后散客可凭码签到；也可找其他队伍新申请，队长拒绝时必须填写正当理由，否则产生 20 元资源占用费与信用扣分。
4. **迟到 / 爽约 / 超时**：B002 散客联队预置了迟到 23 分钟与无理由拒拼扣费；把时钟推过某待开场场次开场 20 分钟，看板/后台出现「释放场地」（R-LATE-1）；对进行中场次持续推时过 20:05 可见超时费 2 元/分钟、超 15 分钟可强制清场（R-OT-2）；B006 是已结算的超时案例。
5. **照明故障（I-005）**：事件页 → B区 H1 故障工单 → 管理员核验后由队伍三选一：等维修 / 改约（押金全退、优先排位）/ 全额退款，费用计时此前已自动冻结（R-LIGHT-3）。
6. **下雨地滑 / 篮筐维修**：后台「场地状态控制」可发布积水暂停/湿滑/恢复（R-WX-1）；B005 预置了篮筐紧急维修改约 + 5 元交通补偿案例（R-WX-2）；I-002 是已裁决的争抢篮筐工单（R-DISPUTE-1）。
7. **噪声投诉 / 未成年人夜留**：以社区工作人员身份处理 I-001（首次劝导 vs 24h 内第 2 次核实收 50 元，R-NOISE-1）、I-004（监护人接回登记，R-MINOR-1）。
8. **封场（I-006）**：管理员对河滨 H3/H4 的社区活动工单签发封场令 → 仅受影响的 B009 被中止、押金全退、可免费改约；同场地正在打球的 B003（H1/H2）不受影响；场地页/看板对应半场显示"封停"（R-SEAL-1）。
9. **现场看板**：任意身份都能看到每个半场当前使用者、签到码、到场人数、剩余/超时时间，以及争议时"预约码→时段比对→先到先得+信用分"的判断指引；积水暂停的半场显示"🌧️ 积水暂停 · 等待改约"。
10. **公平性解释**：管理后台有黄金时段固定队 ≤60% 的配额条；规则页顶部给出改约优先级链（安全维修 > 已支付已签到 > 固定队 > 先到先得 > 信用分），每张被改约卡片（B005/B009 等）都有管理员说明与规则编号，解释"为什么是这一方被改约/限制"（R-FAIR-1~4）。

## 页面与模块

```
src/
├─ App.vue                 手机外壳、顶栏角色切换、演示时钟、底部导航、通知
├─ types.ts                领域模型（场地/预约/队员/费用条目/事件工单/拼场申请/积水暂停…）
├─ store.ts                响应式状态 + 全部业务动作（预约/签到/拼场/照明结算/释放/封场/改约/积水暂停四选一）
├─ data/
│  ├─ mock.ts              4 片场地（含室内馆）、12 个预约、6 个事件工单、4 个拼场申请（覆盖题目全部情形）
│  └─ rules.ts             21 条规则条文（预约拼场/到场超时/照明/天气积水/争议/噪声/公平）
├─ lib/
│  ├─ engine.ts            规则引擎：实时照明计费、迟到/超时、费用汇总、冲突风险、占用/释放、积水补贴与替代方案计算
│  └─ ui.ts                标签页与规则跳转总线
├─ components/
│  ├─ BookingCard.vue      预约卡片：剩余时间、到场、实时照明费、费用变化、积水暂停横幅（到场人数/等待时长）
│  ├─ RainChoiceBox.vue    积水暂停处置卡：队长四选一 / 管理员代录，含补贴预估与替代方案
│  ├─ RiskTag.vue          风险标签（点击展开原因）
│  ├─ RuleLink.vue         规则编号链接（跳到规则页并高亮）
│  └─ BottomSheet.vue      移动端底部抽屉
└─ pages/
   ├─ CourtsPage.vue       场地状况（地面/篮筐/室内馆/更衣柜/照明收费）+ 预约表单 + 现场上报 + 今日占用
   ├─ MinePage.vue         队长（邀请/签到/拼场审核/照明/结算/积水四选一）与散客（签到码/找拼场/申请进度同步）
   ├─ BoardPage.vue        现场看板：谁在用、还能打多久、积水暂停中、释放/强制清场、争议判断指引
   ├─ AdminPage.vue        后台：时段维度预约/到场/支付/风险、积水暂停发布与处置面板、场地控制、改约、公平性配额
   ├─ IncidentsPage.vue    事件工单：现场核验、退款补偿、投诉答复、处罚全流程留痕
   └─ RulesPage.vue        规则原文与公共资源公平性说明
```

## 已执行的验证

- `npm run build`（含 `vue-tsc --noEmit` 全量类型检查）通过，产物输出到 `dist/`。
- `npm test`（`scripts/smoke.mjs`，用 esbuild 打包 `src/store.ts + src/lib/engine.ts` 后在 Node 执行）**36 项断言全部通过**，覆盖：
  - 回归：照明实时计费（97 分钟 × 0.8 元 × 8 折 = 62.08 元、6 人均摊 10.35 元）、开场 20 分钟未签到可释放；
  - 积水暂停发布：三号场置为积水、B003/B011/B012 三队挂起（21:00 开场的 B009 不受影响）、照明计费冻结、到场人数快照 9/4/0、工单 I-007 生成、全场通知；
  - 补偿规则：到场 3 元/人、等待超 30 分钟 +10 元、完全未到场无补贴；
  - 改约窗口：顺延明日同时段、室内馆全场需 2 个空闲半场、半场拼场匹配 B区 H1；
  - 队长四选一：B011 改到室内场（补贴 22 元、照明按实际 30 分钟计 24 元、同步队员 7 人 + 散客 1 人并通知散客）；管理员代录 B003 顺延（补贴 37 元、照明 64 元）、B012 全额退款（押金 50 全退、无补贴、无照明费）；
  - 恢复使用：场地标记湿滑、工单办结。
- `npm run dev` 启动后，用 `curl` 验证首页（HTTP 200、标题正确）以及全部 `src/**` 模块经 Vite 转换后均返回 200。

说明：本项目为前端交互演示，支付、短信、真实定位等均为页面内模拟；刷新页面会重置为初始演示数据。
